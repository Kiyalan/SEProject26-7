# 用例模型（Use Case Model）

## 参与者（Actors）
| 参与者 | 说明 |
|--------|------|
| 维护者 | 管理仓库、处理 Issue、配置系统 |
| 开发者 | 提问、查看分析结果 |
| GitHub | 外部系统，提供仓库/Issue/PR 数据 |
| AI 服务 | 外部系统，提供问答与分类能力 |

## 核心用例

### UC-01 登录并授权 GitHub
- **参与者**：维护者
- **前置条件**：用户有 GitHub 账号
- **主流程**：
  1. 用户打开登录页
  2. 点击 GitHub 授权
  3. 系统保存 token 并进入主界面
- **原型状态**：按钮跳转演示

### UC-02 接入并同步仓库
- **参与者**：维护者
- **主流程**：
  1. 进入仓库管理页
  2. 选择/添加 GitHub 仓库
  3. 系统同步 README、Issue、代码索引
  4. 展示同步状态
- **原型状态**：仓库列表 + 同步状态 Mock

### UC-03 仓库智能问答
- **参与者**：开发者、维护者
- **主流程**：
  1. 选择目标仓库
  2. 输入自然语言问题
  3. 系统分类为 What/Where/How
  4. 返回回答与代码引用
- **原型状态**：聊天 UI + 假回复

### UC-04 Issue 智能分析
- **参与者**：维护者
- **主流程**：
  1. 系统获取新 Issue
  2. 识别类型（使用/重复/信息不足/Bug/功能）
  3. 生成摘要与建议回复
  4. 维护者审阅并决定是否发布
- **原型状态**：列表筛选 + 详情分析面板

### UC-05 浏览知识库
- **参与者**：开发者、维护者
- **主流程**：
  1. 查看目录树与模块划分
  2. 查看依赖关系
  3. 跳转到相关文件（后续）
- **原型状态**：树形结构 + 模块卡片

### UC-06 系统配置
- **参与者**：维护者
- **主流程**：配置 GitHub Webhook、模型 API、功能开关
- **原型状态**：设置页表单

## 用例关系（简述）
- UC-02 是 UC-03、UC-04、UC-05 的前置依赖
- UC-04 在阶段三扩展为自动 PR（进阶用例）

## 阶段一演示路径（评审用）
`UC-01 → UC-02 → UC-04 → UC-03`
